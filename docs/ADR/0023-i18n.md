# ADR-0023: i18n library and country-driven formatting

Status: Accepted; next-intl superseded by `use-intl` with precompiled, per-route messages (ADR-0045) · Date: 2026-10-16 · Deciders: planning session (research: `docs/research/stack-frontend.md` §8)

## Context

English at launch, pt-PT and German next (ADR-0008); the UI language and the user's country are separate settings, and numbers and dates must follow the country (an English UI for a Portuguese user shows `1 234,56 €` and `16/10/2026`). CLDR has no `en-PT` data: `Intl.NumberFormat('en-PT')` silently falls back to `en`. The locale is a user setting stored locally, not a URL segment, which also suits the static-export host.

## Options considered

| Library | Model | Client size | Fit |
|---|---|---|---|
| **next-intl 4.14.9** | runtime ICU messages | 11 kB brotli plus the active locale's messages | first-class App Router support; a provider mode that needs no routing, no `i18n/request.ts`, no proxy; `createFormatter({ locale })` per instance from `use-intl/core` |
| Paraglide JS 2.29.0 | compile-time message functions | 1–2 kB plus messages | strongest on bytes, but with a user-selected locale all languages compile into every function unless the bundler splits them (Turbopack does not run the plugin), no official Next App Router adapter in v2, ICU plural/select through a plugin |
| Lingui 6.10.0 | macros plus ICU catalogs | moderate | depends on an SWC plugin through an experimental Next hook |

## Decision

**next-intl 4.14.9 in client-provider mode**:

- The app layout renders `<NextIntlClientProvider locale messages timeZone formats>` from a client component that loads `messages/<locale>.json` with a dynamic import; only the active locale ships.
- Messages are colocated per feature (`packages/app/features/<feature>/messages/{en,pt-PT,de}.json`) and merged into one object per locale by a small build step; namespaces mirror feature names (`today.primary.boughtAsPlanned`); every key carries a description for translators; type-safe keys through the `AppConfig` augmentation and `createMessagesDeclaration`.
- **Two formatters** through a `useFormatters()` hook in `packages/app/lib/format`: `numbers = createFormatter({ locale: formattingLocale, timeZone })` for currency, percent, units and numeric dates, and `text = createFormatter({ locale: uiLocale, timeZone })` for month and weekday names, relative time and lists. `formattingLocale` comes from a curated country map (`PT → pt-PT`, `DE → de-DE`, `IE → en-IE`, `GB → en-GB`, `BE → nl-BE` or `fr-BE` by UI language, `US → en-US`, …) held in the country profile (`numberFormatLocale`, `dateFormatLocale`).
- Amounts are passed to the formatter as decimal strings (ADR-0017); `formatToParts` styles the parts; the `minusSign` part is replaced with U+2212 because ICU emits a hyphen-minus in the launch locales; currency symbol placement follows the locale (`1 234,56 €` in pt-PT and de-DE, `€1,234.56` in en-IE).
- Numeric input parsing uses the same formatting locale: group and decimal symbols from `Intl.NumberFormat(formattingLocale).formatToParts(1234.5)` (ADR-0034).
- A lint rule flags user-visible string literals in components; the banned-words lint runs over the message files.

## Consequences

- No locale in URLs; sharing a link never carries a language; the legal pages exist in English at launch and in pt-PT and de when those locales ship.
- Translators receive one JSON per locale with descriptions; pluralisation uses ICU in the messages.
- Switching to Paraglide later would be mechanical (the same keys and ICU-compatible messages) if bytes ever force it.

## Disagreement

None.

## Corrections recorded on 2026-10-18

The decision stands; these statements of the text above are not true of the repository, and are
corrected here instead of rewritten (`docs/ADR/README.md`).

- **Context: "English at launch, pt-PT and German next (ADR-0008)".** ADR-0041 moves pt-PT and
  German to the launch, in M2 (ADR-0041, Consequences; `docs/ROADMAP.md` M2).
- **Decision, second bullet: "every key carries a description for translators"; Consequences: "with
  descriptions".** No message carries a description: the message files hold plain ICU strings, and
  the merge tool's `MessageTree` (`tools/messages/merge.ts`) allows only strings as leaves.
- **Decision, third bullet: "Two formatters through a `useFormatters()` hook", each a
  `createFormatter`.** The formatting layer is `createFormatters(formattingLocale, uiLocale)` in
  `packages/app/src/lib/format/index.ts`, built on `Intl` directly; there is no `useFormatters()`
  hook, and use-intl's `createFormatter` is not used. Times and relative days are in `./time`, the
  numeric-input parser in `./number-input`.
- **Decision, fifth bullet: "`formatToParts(1234.5)`".** The parser reads the symbols from
  `formatToParts(1234567.5)`: pt-PT and es-ES group only from five digits, so `1234.5` shows them no
  group symbol (ADR-0034, readings; `packages/app/src/lib/format/number-input.ts`).

## Corrections recorded on 2026-10-20

- **Context: "numbers and dates must follow the country (an English UI for a Portuguese user shows
  `1 234,56 €` and `16/10/2026`)"; Decision, third bullet: the formatting locale for "numeric
  dates".** Numbers follow the country; dates in copy do not. A date carries the month's name in the
  UI language (`4 Mar 2028` in English, `4. März 2028` in German, `4 de março de 2028` in Portuguese,
  where CLDR's short month is digits), so no date reads two ways across countries in one language: in
  digits, an English UI would write a Portuguese plan's date day-first and a US plan's month-first,
  and `Tax-free from 04/03/2028` could be read as 3 April. The country's numeric order
  (`localesFor().dates`, `packages/app/src/lib/i18n/locale.ts`) applies only where digits are needed,
  if anywhere; nothing in copy uses it. Clock times and numbers stay in the formatting locale; the
  date options are `dateOptions` in `packages/app/src/lib/format/time.ts`.

## Corrections recorded on 2026-10-29

- **The 2026-10-18 correction's "there is no `useFormatters()` hook".** There is one:
  `useFormatters()` in `packages/app/src/lib/services/hooks.ts` returns the services'
  `createFormatters(formattingLocale, uiLocale)` for the UI language and the plan's country.
  use-intl's `createFormatter` is still not used.
